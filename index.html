Belajar Github & Git

Git dan GitHub adalah dua alat penting dalam dunia pengembangan perangkat lunak yang sering digunakan secara bersamaan, namun memiliki fungsi yang berbeda. Git adalah sistem kontrol versi (Version Control System/VCS) yang memungkinkan pengembang melacak perubahan pada kode sumber secara lokal. Dengan Git, setiap perubahan yang dilakukan pada proyek bisa dicatat, dibandingkan, dan dikembalikan ke versi sebelumnya jika diperlukan. Git bersifat terdistribusi, artinya setiap pengembang memiliki salinan penuh dari repositori proyek, yang memungkinkan kolaborasi yang efisien bahkan tanpa koneksi internet.

Sementara itu, GitHub adalah layanan berbasis cloud yang menyediakan antarmuka grafis dan ruang penyimpanan untuk repositori Git. GitHub memungkinkan kolaborasi antar pengembang secara online, termasuk fitur seperti pull request, issue tracking, dan CI/CD. Menurut Linus Torvalds, pencipta Git, dia menciptakan Git karena tidak menemukan sistem kontrol versi yang sesuai untuk pengembangan kernel Linux—ia ingin sesuatu yang cepat, terdistribusi, dan memiliki integritas data yang tinggi. Sedangkan menurut Scott Chacon, salah satu penulis buku Pro Git dan mantan CIO GitHub, GitHub menjadikan Git lebih mudah diakses oleh semua orang dengan menyediakan platform kolaborasi yang intuitif.

1. git init
Ini akan membuat folder .git tersembunyi di dalam direktori kerja kamu. Folder ini menyimpan semua data dan metadata git, seperti commit history, konfigurasi, dan lain-lain. Setelah git init, folder kamu resmi jadi "proyek Git".

2. git add .
git add dipakai untuk menambahkan file ke staging area, yaitu area sementara sebelum di-commit. Titik . berarti “semua file yang berubah” — bisa file baru, file yang diedit, atau yang dihapus.

3. git commit -m "Commit pertama: inisialisasi proyek dengan README"
Perintah ini menyimpan snapshot dari semua file yang ada di staging area. -m berarti kamu menuliskan pesan commit langsung di baris perintah (bisa juga tanpa -m, tapi nanti masuk ke editor). Pesan commit penting buat dokumentasi perubahan.

4. git remote add origin https://github.com/username/nama-repo.git
Di sini kita menghubungkan repositori lokal ke repositori GitHub.

  • origin adalah nama default untuk remote utama. Kamu bisa ganti, tapi ini konvensi umum.
  • URL itu adalah alamat dari repo yang kamu buat di GitHub.

5. git config
Perintah ini dipakai untuk mengatur identitas pengguna di Git. Biasanya kamu atur ini sebelum commit pertama, supaya Git tahu siapa yang bikin commit-nya.

  • git config --global user.name "Nama Kamu"
  • git config --global user.email "emailkamu@example.com"

6. git push
git push -u origin main

  • push artinya mengirim semua commit dari branch lokal ke remote (GitHub).
  • origin itu nama remote yang kamu set sebelumnya (git remote add origin).
  • main adalah nama branch yang mau dikirim.
  • -u artinya Git akan menghubungkan branch lokal ke branch remote — jadi ke depannya kamu bisa cukup ketik git push saja, tanpa harus sebut nama remote/branch lagi.
